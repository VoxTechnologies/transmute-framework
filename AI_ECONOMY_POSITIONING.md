# Transmute Framework — Position in the AI Economy

> A short strategic note. The Transmute Framework (this MIT plugin) and Transmuter (the proprietary SaaS at transmuter.3mergen.com) are analyzed in depth against a structural "AI substitutes for labor" framework in a separate private research vault. This note records the connection at a high level; the framework repo carries only the public-facing summary.

----

## Why Plan Casting is the right shape

Plan Casting bets that the marginal cost of *building software* collapses toward zero — so you build everything in the plan (no MVP, no feature cutting), in priority order. That is the deepest expression of "deflationary abundance": as model capability commoditizes, *generation* gets cheaper for everyone.

The strategic consequence: **generation is not the moat.** "AI can write a product" becomes table stakes as frontier models improve. What endures is the **gate-enforced verification** — the 5B / 6V / 6R / 7V gates and the human review checkpoints — that turns raw generation into something you can trust in production. The pipeline's value is "verified, deployable output," not "more output faster."

This is the same principle across the author's stack: bet on the verification / accountability layer (durable), not the capability / generation layer (commoditizing).

## Framework (MIT) vs Transmuter (SaaS): the layer split

This framework is the open funnel — free, forkable, lowers the cost of trying Plan Casting. Transmuter is the rent layer — isolated execution (E2B microVMs), durable orchestration (Convex Workflows), multi-tenancy, and metered billing that a local plugin cannot provide. The commodity layer is given away; the value accrues to the operated layer above it.

## agent-as-customer

Each Plan Cast has agents hire factors of production — compute (E2B sandboxes) and models (the Claude API) — to build a product. That is a concrete instance of the emerging "agents hire things" layer of the AI economy, with real metered payment behind it.
